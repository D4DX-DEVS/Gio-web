# giokerala.org: pre-migration audit

- **Audit date:** 27 October 2026
- **Method:** read-only. Public HTTP requests only (sitemaps, the public WordPress REST API, rendered HTML, Elementor CSS, HEAD checks on files). Nothing was logged into, submitted or changed on the live site.
- **Raw evidence:** `migration/snapshot-2026-10-27/` (REST JSON, 139 rendered HTML pages, Elementor CSS, asset HEAD results). The scripts that produced it are in `migration/scripts-audit/`.
- **Detailed inventories:** `docs/audit/inventory/`
  - `url_inventory.csv`: every URL found, with status, type, sitemap source, widgets used
  - `posts.csv`: all 34 posts with dates, category, featured image, image and word counts, data-quality notes
  - `leaders.csv`: 123 leader entries parsed from the three leader pages
  - `asset_inventory.csv`: every image and document, whether the media API lists it, alt text, and where it is used

---

## 1. Executive summary

1. **The site runs on WordPress 7.1.3** with the Hello Elementor theme and Elementor 4.2.4, served by LiteSpeed behind **Cloudflare** (the domain is already proxied by Cloudflare, which makes the cutover simple).
2. **The public REST API is open** and gives clean, structured data for posts, pages, media, categories, tags and events. **That is the main migration path for editorial content, and it is more reliable than scraping.** Scraping is still needed for content that lives only inside Elementor widgets (leaders, homepage sections, header menu).
3. **The real content is small and well-bounded:** 34 posts, 11 real pages, 3 calendar events, 123 leader entries, 1 featured YouTube video, 3 PDFs, and about 345 unique files (≈364 MB of originals).
4. **About 61 public URLs are leftover demo content** from a previous charity theme ("Savelife"): placeholder testimonials, FAQs about "Visual Composer license keys", "Charity poor peoples" projects and a "New York" marathon event. They need a keep/drop decision; we have **not** silently dropped them.
5. **Some content is not reachable without admin or database access:** menus, Elementor's structured page data, drafts/private/scheduled posts, revisions, contact-form submissions, 34 media items that the API counts but does not list, plugin settings, and user accounts. Section 8 lists exactly what to request.

### 4.1 Images: things the plan has to handle

- **20 files are used on public pages but not returned by the media API.** Among them are hero slides `bnr1-5.jpg`, the programme logos (`akshra`, `h-meet`, `herizon`, `nerinte`, `proteen`, `Group-4`), `madayi-case.png`, two leader photos, the Naqaba event image and two Elementor CSS background images. 17 of them download fine; 3 (`2020/10/event-1.jpg`, `event-2.jpg`, `graph.png`, used only on demo pages) already return 404 *(corrected 27 Oct, see `04-STATUS-AND-DECISIONS.md` §2)*. **The migration must use the full file list, not just the media API.**
- **82 media-library items are not used on any public page.** They will be migrated anyway: unused does not mean unwanted.
- **No image has alt text** (all 301 listed media items have an empty `alt_text`; corrected 27 Oct from "about 296"). We will not invent alt text. The admin media module will flag these for editors to fill in.
- Elementor CSS sets 4 background images (on the homepage and the GIO News header). These are invisible to HTML scraping and were found by scanning the CSS.
- Posts reference resized copies (`-300x200.jpg`, `-1024x683.jpg`, `-scaled.jpg`). Only originals will be stored; the old resized URLs will still resolve (see architecture §4).

## 8. What cannot be accessed publicly, and what to request

| Not accessible | Why it matters | Request |
|---|---|---|
| **Database** (`wp_posts`, `wp_postmeta`, `wp_options`, `wp_terms`) | Drafts, private and scheduled posts, revisions, Elementor's structured `_elementor_data` (exact homepage sections, carousel link targets, leader widget order), menu definitions, TEC settings | **Full MySQL dump** (phpMyAdmin / hosting panel → Export, gzip), or at least *Tools → Export → All content* (WXR) |
| **34 media items** (API reports 335, lists 301) | They are attached to non-public content or hidden; some may be needed | Included in the DB dump + uploads archive |
| **`wp-content/uploads` folder** | Guarantees byte-exact originals, including files never linked anywhere (directory listing is correctly blocked) | **ZIP of `wp-content/uploads`** from hosting file manager / SFTP |
| Menus, menu locations, widgets, settings | REST returns 401 | DB dump or a read-only admin account |
| **Contact form submissions** | Messages may be stored in WordPress (Royal Addons form submissions) or only emailed; unknown | Confirm where messages go today, and export any stored submissions |
| Contact Form 7 forms | REST returns 401; probably unused | Confirm unused |
| User accounts | Email addresses and roles for the new admin | List of people who need admin access and their roles (passwords are **not** migrated; users set new ones) |
| Instagram feed token | Needed to keep the live feed | Instagram account owner connects a Meta app, or approves an embed-only fallback |
| Tamkeen (`tamkeen.rehours.com`) | External app; we only embed it | Confirm owner and that embedding should continue |
| Zoho form | External | Confirm it stays external |
| Cloudflare account / DNS | Cutover and R2 / D1 / Workers setup | Access to the Cloudflare account that already proxies giokerala.org (or a new account plus a DNS change) |
| Source code / theme customisations | Hello Elementor is a stock theme; customisations are probably in Elementor data, not code | Confirm there is no custom plugin or child theme (or send `wp-content/themes` + `wp-content/plugins` list) |

Without these, we can still migrate **all public content** from the snapshot. The items above would be missing or would have to be reconstructed by hand from HTML.

## 9. Migration methods available (ranked)

1. **WordPress database dump + uploads archive (requested).** Most complete. Includes unpublished content, Elementor JSON and menus. Lets us run the import offline and repeat it.
2. **Public REST API (available now, snapshot taken).** Covers posts, pages, media metadata, taxonomies, events, venues, organizers and SEO metadata. Structured and reliable for what it exposes.
3. **Rendered HTML parse (available now, snapshot taken).** Needed for leaders, homepage sections, the header menu, contact details and Elementor CSS backgrounds. Reliable for this site's size, and every parsed item is listed in the inventory CSVs so it can be checked by eye.
4. **Direct file download by URL (available now).** 342 of 345 files return 200; this covers the 20 files the API does not list.
5. **WXR export (fallback if no DB dump).** Covers posts, pages, attachments, menus, CPTs and drafts, but not plugin settings or Elementor CSS.

**Plan:** use 2 + 3 + 4 now to build and test the importer against real data; switch the importer's input to 1 when the dump arrives; use the dump to fill the gaps in §8 and to cross-check counts.
